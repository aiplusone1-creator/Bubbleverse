# Bubbleverse — MVP execution roadmap

Baseline: `71a0d853920771f3469160cf142de4944ab28b0c`, audited 2026-11-14. This is a proposed implementation plan, not completed work or authorization to deploy. Findings A01–A25 and evidence/uncertainty are in [AUDIT.md](AUDIT.md). P0 critical blockers precede public beta; P1 is required for the paid MVP; P2 follows MVP; P3 preserves future options.

## Constraints and architecture decision

Keep React/TypeScript/Vite/Supabase and existing UI/animation identity. Use additive migrations, small service modules and narrowly scoped component wiring. Do not remove features, rewrite UI, change production data, deploy, or purchase services as part of this audit. Approval is required before adopting a paid provider. Use synthetic identities/photos and isolated infrastructure for implementation verification. Avoid replaying the credential-seeding migration against any connected database.

## Recommended first implementation task

After owner-led handling of A01, protect profile privilege fields. Add a focused migration restricting ordinary users to display_name/avatar_url/preferred_currency, while preserving explicitly authorized admin operations and signup trigger behavior. RLS row checks alone cannot distinguish allowed columns: choose reviewed column grants plus safe admin RPC, or a carefully tested field-protection trigger. Cover both INSERT and UPDATE, direct Data API access, denied premium/self-unban, authorized admin change and allowed preference edits. No UI redesign, new paid provider or production data mutation is needed to review this change. Keep parent/child integrity as the next focused security PR.

## Sequencing commerce and spend

Proposal: validate the full digital-book flow before public charging. Product must choose when to charge relative to costly illustration generation. If generation precedes payment, enforce preview quotas/caps and quantify abandoned-generation cost. If payment precedes completion, publish clear pending/failure/refund behavior. Do not silently assume premium subscriptions; existing premium toggle does not define a commercial product. Currency preferences are display preferences, never authoritative payment amounts.

## P3 extension boundaries

Hardcover: consume an immutable approved book/PDF version with future print preflight, fulfillment adapter, shipping order/events and address privacy. Video: consume versioned scene/character assets through an independent asynchronous renderer and separate entitlement/cost policy. Acceptance for this MVP is an architecture that does not conflate payment, book readiness and physical/video fulfillment; neither extension is implemented.

## Decisions and remaining unknowns

Deployment history/RLS grants, Lovable credential portability, providers' child-photo retention/training terms, operating jurisdiction and parental-consent requirements, payment merchant availability/currencies/tax/refunds, agreed PDF page dimensions, expected volume and unit-economics target require confirmation from owners or isolated experiments. They are unverified dependencies, not evidence of present production behavior. No duration/cost commitment is credible until provider benchmarks and account access are available.

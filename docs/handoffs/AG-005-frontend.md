# AG-005 frontend handoff for inquiry staging

Start from branch `codex/AG-005-order-pipeline-backend` at `d2b1edc11bcf049d9c37bc877ac650d89397fe22`. This is a staging-only integration prompt for the implemented inquiry workflow. Keep AG-004 design files and saved-story library behavior. Frontend owns the wizard, order pages, staff queue and Studio views. Backend files, policies and contracts remain owned by Codex.

Use the Supabase authenticated client and generated-shape RPC declarations in `src/integrations/supabase/types.ts`. Use `getOrderQuote` and `createStoryInquiry` in `src/features/orders/orderService.ts`. Keep one UUID requestKey per logical input and retry on transport failure with that key. A materially edited submission takes a new key.

- `get_story_order_quote(p_country, p_format)` returns currency, version, totalMinor, depositMinor and checkoutEnabled. Null amounts indicate missing pricing. Checkout is always disabled in this foundation.
- `create_story_inquiry(p_request_key, p_country, p_format, p_language, p_child_first_name, p_shipping_address)` returns id, reference, status, country, format and currency. EG maps to EGP and SA to SAR. Formats are digital_pdf and hardcopy_book. Languages are ar and en. Digital requires null shipping. Hardcopy requires a nonblank shipping address.
- `list_story_orders(p_before?)` returns up to 50 owner summaries with snake_case keys. The profile must preserve its existing saved-story library. Use `get_story_order(p_order_id)` for detail. It returns camelCase fields and adds assignedOperatorId/internalNotes only for staff with access.
- `is_order_staff()` checks active staff eligibility. Do not relax existing admin routes. `list_order_queue()` returns up to 100 redacted rows with snake_case keys. Unassigned eligible rows, assigned rows and admin visibility follow the RPC.
- `claim_story_order(p_order_id)` requires operator role and returns the claimed UUID. `assign_story_order(p_order_id, p_operator_id)` requires admin and an eligible operator. Refresh when a claim returns PT409.
- `request_order_correction(p_order_id, p_message)` is available to authorized assigned staff/admin on eligible intake orders. `correct_story_order(p_order_id, p_child_first_name, p_shipping_address)` is owner-only during needs_customer_update. Both return void. Correction clears the request and returns the order to the appropriate review state.
- `submit_b2b_inquiry(p_institution, p_contact_name, p_contact_email, p_contact_phone, p_country, p_format, p_language, p_quantity, p_notes)` returns a UUID. Keep public B2B portal UI out of scope.
- Handle 42501 as denied, PT404 as unavailable, PT409 as a state or idempotency conflict, and validation SQLSTATEs 22023/23xxx as invalid input. Translate messages locally.

Keep StoryWizard on Index and replace direct AI calls with inquiry submission when releasing this flow. Preserve entered fields across steps. Show order reference after successful submission.

# UI task router

Read repository-root `AGENTS.md`, `CODEX_DIRECTIVES.md`, and `DESIGN.md` when relevant.
Use the current HEAD and task file allowlist; preserve user changes. These are project-authored
instructions adapted from the supplied reference collection, not the missing upstream resources.
No fixed greeting, automatic worktree/subagent, hidden paid call, or extra approval loop.

1. Read DESIGN.md and CODEX_DIRECTIVES.md, then classify the request as audit, implementation, exploration or explanation.
2. Choose one primary specialist from docs/skills/INDEX.md; add only a needed reference, not the entire collection.
3. Use mobile-native/break-ui for mobile/RTL/state failures, animate/choreograph for implementation, review-animations for a diff, and animation-performance for measured jank.
4. Use prototype and learn-taste only on explicit relevant requests. A skill reference never overrides the user's authorized scope.
5. The product goal is a complete safe storybook purchase/delivery flow. UI polish must not consume the budget or block independent backend work.
6. State what was tested and what needs actual browser/device/client access.
